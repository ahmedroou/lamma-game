# إصدارات Android والتحديث من التطبيق

قرار 14 أكتوبر 2026: نشر إصدارات APK على مستودع المشروع العام `ahmedroou/lamma-game`. يتحقق المستخدم من التحديث من «الإعدادات ← تحديث التطبيق»، وينزل APK داخل التطبيق ثم يفتح تثبيت Android. يلزم اتصال للفحص والتنزيل فقط؛ الأسئلة والبيانات المحلية تبقى كما هي عند التحديث دون حذف التطبيق.

## المصدر والصيغة

- المستودع: https://github.com/ahmedroou/lamma-game
- آخر إصدار مستقر: `https://api.github.com/repos/ahmedroou/lamma-game/releases/latest`.
- اسم الأصل لكل إصدار: **lamma-android.apk**، وهو APK شامل لمعمارية ARM64 وARMv7 وx86_64.
- وسم الإصدار: **vVERSION+BUILD**، مثل `v0.2.0+2`. مصدر القيم `version` في pubspec.yaml. كل تحديث يجب أن يزيد BUILD، حتى إذا لم يتغير الاسم التسويقي للإصدار.
- الفحص يبدأ بملف `update.json` الصغير من `/releases/latest/download/update.json`، ثم يعود إلى API إذا لم يتوفر الملف أو تعذر قراءته. يُرفع الملف مع APK ضمن المسودة ويُتحقق من بصمته قبل نشرها، فلا يحتاج الفحص المعتاد إلى حصة GitHub API المجهولة.
- لا يسحب التطبيق Draft أو Prerelease. لا يضع أي رمز دخول GitHub داخل التطبيق.
- زر صغير ثابت أعلى الرئيسية يفتح صفحة التحديث، وعليه نقطة إشعار فقط عندما يكون رقم البناء المنشور أكبر من المثبت. يبدأ فحص Android تلقائيًا عند فتح الرئيسية، ويتكرر كل 15 دقيقة وهي ظاهرة وفي المقدمة، وعند الرجوع للتطبيق إذا انقضت المدة. لا اتصال مطلوب للعب، ولا فحص تلقائي أثناء عرض شاشة اللعب أو في الخلفية، ولا تنزيل أو تثبيت تلقائي.
- مقارنة روابط APK تستخدم مقاطع URI المفكوكة مرة واحدة، فتقبل ترميز GitHub الرسمي `%2B` لعلامة `+`، مع استمرار رفض المصادر الخارجية والترميز المزدوج والمقاطع الملتبسة والمنافذ والاستعلامات غير المتوقعة.
- يلزم أن يظهر `digest` من نوع SHA-256 وحجم صالح في بيانات أصل GitHub؛ لا يقبل التطبيق إصدارًا ناقص البيانات أو رابط تنزيل خارج المستودع المحدد.

## التوقيع

معرف التطبيق ثابت `com.lamma.lamma`. إصدارات Release تستخدم توقيع production حقيقي، ولا تستخدم مفتاح debug. إعدادات التوقيع المحلية في android/key.properties مستبعدة من Git؛ المفتاح الدائم ونسخة خصائصه موجودان خارج المشروع في:

`C:/Users/Admin/.local/share/lamma-signing/`

احتفظ بنسخة آمنة من هذا المجلد. فقدان المفتاح أو تغييره يمنع تحديث التطبيقات المثبتة بهذا التوقيع. لا ترفع ملف JKS أو كلمات المرور أو key.properties إلى المستودع أو الإصدارات. على جهاز بناء آخر، انقل المفتاح بأمان وأنشئ android/key.properties بالقيم الأربع storeFile/storePassword/keyPassword/keyAlias. خصائص البناء غير السرية تستخدم SDK وJava المحليين.

## نشر الإصدار التالي

1. حدّث `version` في pubspec.yaml، مع زيادة رقم BUILD.
2. أتمم مراجعة التغييرات والتحليل والاختبارات المناسبة. نجاح اختبار البنية لا يعني مراجعة جميع حقائق بنك الأسئلة.
3. احفظ مصادر الإصدار في Git وارفعها؛ لا تجمع تغييرات غير مكتملة من أجنت آخر في إصدار دون مراجعتها.
4. شغّل `scripts/publish_android.ps1` من مجلد Flutter، ومرّر ملف ملاحظات الإصدار. يحتاج Flutter/Android SDK/Java وgh مسجّلًا بالحساب المخوّل.
5. السكريبت يبني APK موقّعًا، يتحقق من توقيعه واسم الحزمة والإصدار، ينشئ Release مسودة ويرفع APK وبصمته، ويتحقق من تطابق حجم وبصمة أصل GitHub، ثم ينشره كآخر إصدار. عند فشل التحقق تبقى المسودة ولا يراها فحص التطبيق.
6. يُرفض إعادة نشر نفس الوسم؛ لا تستبدل APK منشورًا بملف آخر تحت الإصدار نفسه. أنشئ رقم BUILD جديدًا.

مثال PowerShell:

```powershell
./scripts/publish_android.ps1 -NotesPath ./RELEASE_NOTES.md
```

## التنزيل والتثبيت

التنزيل تدفقي إلى cache خاص بالتطبيق دون تحميل APK كله إلى الذاكرة. تظهر النسبة ويمكن الإلغاء. يُرفض انقطاع التنزيل أو اختلاف الحجم أو SHA-256، وتُزال الملفات الجزئية. قبل كل محاولة تثبيت يُعاد التحقق من الملف، وتحفظ المباراة؛ فشل حفظ المباراة يمنع بدء التثبيت.

على Android 8 فأحدث قد يحتاج المستخدم تفعيل «السماح من هذا المصدر» للتطبيق مرة واحدة، ثم العودة والضغط على «تثبيت التحديث». لا تُثبّت APKs بصمت ولا يغيّر التطبيق الإذن بنفسه. يُشارك ملف واحد في مجلد app_updates عبر FileProvider غير مصدّر. تُفحص حزمة APK ورقم البناء وشهادة توقيعها مقابل التطبيق المثبت، ثم يتحقق نظام Android من صحة التوقيع ويطلب تأكيد المستخدم. فتح نافذة النظام لا يُسجّل كنجاح تثبيت؛ الإصدار المثبت يُقرأ من PackageManager عند تشغيل التطبيق.

نسخة الويب تعرض رابط تنزيل Android ولا تحاول تثبيت التطبيق. تثبيت iOS مباشرة من GitHub غير مدعوم بهذا المسار؛ يحتاج توزيع iOS معتمدًا وبيئة macOS/Xcode وتوقيع Apple.

مراجع التنفيذ: GitHub Releases REST API، وAndroid PackageManager.canRequestPackageInstalls وFileProvider. اختبارات التحديث في test/features/app_update_test.dart وapp_update_widget_test.dart. اختبار التثبيت الفعلي على جهاز Android مطلوب عندما يتوفر جهاز.
